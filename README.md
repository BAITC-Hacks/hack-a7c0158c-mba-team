# AI Sana — каталог практических бизнес-задач

MVP для кейса HackAlem AI. Представитель бизнеса превращает краткое описание проблемы в понятную карточку, а студенческие команды изучают каталог и предлагают решения. Бизнес вручную выбирает одну или несколько команд и подтверждает выполненные этапы.

## Что реализовано

- Черновик бизнес-задачи и три уточняющих вопроса. Если задан `OPENAI_API_KEY`, вопросы готовит OpenAI; при ошибке или отсутствии ключа включается детерминированный демо-режим.
- Редактируемая карточка перед публикацией и повторное редактирование после публикации.
- Прозрачный рейтинг готовности 0–100 с разбивкой по критериям и подсказками.
- Каталог с фильтрами и сортировкой. Опубликованные задачи с низким рейтингом остаются видимыми.
- Отклик команды: идея, план, срок и необязательная ссылка на прототип.
- Ручной выбор или отклонение каждого отклика; выбор команды не меняет решения по другим откликам.
- Подтверждение бизнесом выполненного этапа выбранной команды: +10 баллов за этап.
- SQLite для карточек, команд и откликов. Данные хранятся на сервере и доступны разным браузерам, подключённым к одному запущенному экземпляру приложения.
- Пять синтетических задач, профилей команд и откликов для демонстрации. При первом запуске они добавляются без перезаписи сохранённых записей.

## Технологии и архитектура

- Next.js 16 App Router, React 19, TypeScript.
- SQLite через `better-sqlite3`; файл базы создаётся в `data/ai-sana.db` и исключён из Git.
- OpenAI Responses API для уточняющих вопросов — необязательно; ключ хранится только на сервере.
- API-маршруты `/api/tasks`, `/api/proposals`, `/api/teams` читают и изменяют общее хранилище. Клиентские экраны обновляют данные с сервера.
- Основной путь: бизнес публикует задачу → команда отправляет отклик → бизнес принимает решение → бизнес подтверждает этап → команда видит статус и баллы.

## Установка и запуск

Требуется Node.js 20.9 или новее.

```bash
npm install
cp .env.example .env.local
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). OpenAI-ключ для основного сценария не обязателен: без него работают демонстрационные вопросы. Чтобы включить AI, добавьте `OPENAI_API_KEY` в `.env.local`. Не коммитьте `.env.local` и не размещайте ключи в клиентском коде.

## Повторяемый сценарий для жюри

1. Откройте «Каталог задач», выберите любую задачу и отправьте отклик от имени команды.
2. Откройте «Отклики» → «Смотреть отклики». Проверьте идею, план и срок, затем нажмите «Выбрать команду» у одного из предложений. Остальные решения останутся независимыми.
3. В выбранном предложении добавьте этап, например «Согласован кликабельный прототип», и подтвердите его. Должны появиться +10 баллов.
4. Откройте ссылку «Проверить статус» из подтверждения отправки: выбранный статус и подтверждённые этапы доступны команде.
5. В «Отклики» → «Изменить карточку» добавьте недостающие данные, сохраните и проверьте пересчитанный рейтинг в каталоге.
6. Для демонстрации бизнес-сценария откройте «Создать задачу», введите вымышленное описание, пройдите вопросы, отредактируйте карточку и подтвердите публикацию.

Данные записываются в SQLite на сервере; для проверки с нескольких устройств откройте один и тот же URL приложения на каждом устройстве. Для локального демо достаточно одного компьютера и двух вкладок.

## Формула рейтинга

| Критерий | Вес |
| --- | ---: |
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |

Уровни: 0–39 — черновик; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная.

## Структура проекта

```text
src/
  app/
    api/                 API уточнений, задач, команд и откликов
    business/            создание, редактирование задач и решения бизнеса
    catalog/             каталог и форма отклика
  features/
    demo/                первоначальное добавление демо-данных
    proposals/           форма отклика, статусы и прогресс
    tasks/               типы, рейтинг и редактор задачи
  lib/
    app-db.ts            SQLite для данных MVP
    auth-db.ts           отдельный экспериментальный сценарий входа
    demo-data.ts         синтетические данные
```

## Данные, ограничения и безопасность

- Используются только синтетические примеры. Описание бизнеса может отправляться в OpenAI при заданном ключе; не вводите персональные, конфиденциальные или реальные закрытые данные. AI-результат перед публикацией проверяет человек.
- SQLite рассчитан на демонстрацию на одном экземпляре сервера с постоянным диском. Для нескольких параллельных серверов или хостинга с эфемерной файловой системой понадобится общая размещённая база данных.
- В MVP нет разграничения бизнес- и командных прав: API решения и подтверждения этапов открыты приложению. Не размещайте версию с реальными данными до добавления авторизации и проверки прав.
- Начальные демонстрационные записи не перезаписывают данные и повторно добавляются только при отсутствии соответствующего ID. Для чистого демо удалите локальный `data/ai-sana.db` и перезапустите приложение.
- Регистрация и подтверждение e-mail — экспериментальный экран и не нужны для основного сценария кейса; для отправки писем нужен `RESEND_API_KEY`.
