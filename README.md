# AI Sana — каталог бизнес-задач

MVP для HackAlem AI: бизнес описывает и публикует практическую задачу, а студенческие команды находят её в каталоге и отправляют предложение. Рейтинг показывает, насколько хорошо подготовлена карточка, и помогает понять, каких деталей не хватает.

## Что реализовано

- Пошаговое создание задачи: черновик, уточняющие вопросы, проверка карточки и публикация.
- Уточнение описания через OpenAI Responses API, если задан серверный ключ. Без ключа используются демонстрационные вопросы.
- Каталог опубликованных задач с рейтингом, уровнем готовности, разбором баллов и подсказками.
- Фильтр по отрасли и готовности, сортировка по рейтингу.
- Форма отклика команды, просмотр статуса и панель решений бизнеса.
- Регистрация и вход с хранением учётных записей в локальной SQLite-базе.
- Демонстрационные задачи, команды и отклики добавляются при первом запуске приложения в данном браузере. Уже сохранённые данные не перезаписываются.

## Основной сценарий

1. Представитель бизнеса вводит описание задачи и отрасль.
2. Приложение предлагает уточняющие вопросы. Ответы можно проверить и отредактировать в карточке.
3. После подтверждения задача получает статус `published` и появляется в каталоге.
4. Команда выбирает задачу, оценивает её рейтинг и отправляет отклик по адресу `/catalog/{taskId}/respond`.
5. Бизнес просматривает предложения и вручную выбирает или отклоняет их. Команда может открыть страницу статуса отклика.

## Архитектура

```mermaid
flowchart LR
  Business[Бизнес] --> NewTask[Конструктор /business/new]
  NewTask --> Clarify[POST /api/clarify]
  Clarify -->|Есть OPENAI_API_KEY| OpenAI[OpenAI Responses API]
  Clarify -->|Ключа нет или API недоступно| Fallback[Демонстрационные вопросы]
  NewTask -->|Подтверждение публикации| LocalTasks[(localStorage: задачи)]
  LocalTasks --> Catalog[Каталог /catalog]
  Catalog --> Scoring[Формула рейтинга]
  Catalog --> Respond[Форма /catalog/{taskId}/respond]
  Respond --> LocalProposals[(localStorage: отклики)]
  LocalProposals --> Dashboard[Решения бизнеса]
  Auth[API авторизации] --> AuthDB[(SQLite: data/ai-sana.db)]
```

**Компоненты:**

- `src/app/` содержит страницы App Router и API-маршруты.
- `src/app/business/new/page.tsx` ведёт создание и публикацию карточки.
- `src/app/api/clarify/route.ts` вызывает OpenAI на сервере или возвращает fallback-вопросы.
- `src/app/catalog/` отображает каталог и локальные стили каталога.
- `src/features/tasks/scoring.ts` содержит формулу рейтинга и уровни готовности.
- `src/features/proposals/` содержит форму отклика, просмотр статуса и управление решениями бизнеса.
- `src/lib/storage.ts` хранит задачи, команды и отклики в браузерном `localStorage` и уведомляет открытые страницы об изменениях.
- `src/lib/auth-db.ts` использует SQLite только для учётных записей, кодов подтверждения, сессий и лимитов авторизации.

## Формула рейтинга

Рейтинг рассчитывается функцией `scoreTask` из `src/features/tasks/scoring.ts`. Непустое значение проверяется после удаления пробелов. Вес критерия начисляется за заполненные поля; критерии из нескольких полей делят свой вес поровну.

| Критерий | Вес | Как распределяется вес |
| --- | ---: | --- |
| Контекст и потребность | 20 | Контекст — 10, потребность — 10 |
| Данные и материалы | 20 | Поле целиком — 20 |
| Ожидаемый результат | 15 | Поле целиком — 15 |
| Критерии успеха | 15 | Поле целиком — 15 |
| Ограничения | 10 | Поле целиком — 10 |
| Пользователи | 10 | Поле целиком — 10 |
| Связь с бизнесом | 10 | Контакт — 5, формат взаимодействия — 5 |
| **Итого** | **100** | |

Название и отрасль нужны для карточки, но не входят в формулу рейтинга. Для каждого пустого поля из критериев показывается подсказка с возможным приростом баллов.

| Баллы | Уровень |
| ---: | --- |
| 0–39 | Черновик |
| 40–69 | Рабочая |
| 70–89 | Готовая |
| 90–100 | Приоритетная |

Низкий рейтинг не скрывает опубликованную задачу: команды могут откликнуться на любую опубликованную карточку.

## Правила каталога

- Каталог включает только записи со статусом `published`.
- Карточка показывает отрасль, название, описание потребности, балл из 100, уровень готовности, шкалу, разбор баллов и подсказки.
- Отраслевой фильтр строится из отраслей опубликованных задач; варианты сортируются по алфавиту.
- Фильтр готовности содержит все четыре уровня.
- Сортировка доступна по убыванию и возрастанию рейтинга.
- Фильтры и сортировка обновляют список на клиенте без перезагрузки страницы.
- Если опубликованных задач нет, показываются сообщение «Пока нет опубликованных задач» и ссылка «Создать задачу».
- Если задачи есть, но ни одна не соответствует фильтрам, показывается сообщение «По этим фильтрам задач нет» с предложением изменить фильтры.
- Ссылка «Откликнуться» ведёт на `/catalog/{taskId}/respond`.

## Технологии и интеграции

- Next.js App Router, React и TypeScript.
- CSS Modules для стилей каталога.
- `localStorage` — демо-хранилище задач, команд и откликов. Эти данные доступны в профиле браузера, где они созданы; серверной общей базы для них пока нет.
- SQLite через `better-sqlite3` — локальное хранилище авторизации в `data/ai-sana.db`.
- OpenAI Responses API — необязательное серверное уточнение бизнес-задачи. Модель по умолчанию — `gpt-4.1-mini`; её можно переопределить через `OPENAI_MODEL`.
- Для production-подтверждения по e-mail код использует Resend и переменные `RESEND_API_KEY` и `AUTH_EMAIL_FROM`. Подтверждение по телефону в production не подключено.
- NVIDIA API в текущей версии проекта не используется.

## Установка и запуск

Требуется Node.js 20.9 или новее.

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Для production-сборки используйте:

```bash
npm run build
npm start
```

Для необязательного AI-уточнения задайте `OPENAI_API_KEY` в локальном `.env.local`. При необходимости укажите `OPENAI_MODEL`. Без OpenAI-ключа конструктор использует демонстрационные вопросы. Для production-подтверждения e-mail также задайте `RESEND_API_KEY` и `AUTH_EMAIL_FROM`. Не добавляйте секреты в GitHub.

## Проверка проекта

### Сборка

```bash
npm run build
```

В `package.json` отдельный тестовый runner не настроен; ниже приведены ручные сценарии для повторения в браузере.

### Каталог, рейтинг и фильтры

1. Запустите приложение и откройте `/catalog`. В новом профиле браузера после инициализации должны появиться пять опубликованных демонстрационных задач.
2. Проверьте полную карточку «Прогноз спроса в магазинах»: рейтинг `100/100`, уровень «Приоритетная».
3. Выберите отрасль «Здравоохранение»: должна остаться задача «Сократить ожидание в клинике» с рейтингом `85/100`. Выберите уровень «Готовая» — эта карточка должна остаться в списке.
4. Проверьте уровень «Рабочая»: должна отображаться задача «Найти лишний расход энергии» с рейтингом `60/100`. Уровни «Черновик» и «Приоритетная» также можно проверить на демонстрационных карточках `30/100` и `90–100/100`.
5. Установите «Все темы» и «Любой уровень». При сортировке сначала по высокому рейтингу ожидается порядок `100, 90, 85, 60, 30`; при сортировке сначала по низкому — `30, 60, 85, 90, 100`.
6. У задачи «Найти лишний расход энергии» откройте «Как повысить рейтинг»: должны быть подсказки про ожидаемый результат `+15`, критерии успеха `+15` и ограничения `+10`.
7. Выберите отрасль «Образование» и уровень «Приоритетная». Должно появиться сообщение «По этим фильтрам задач нет» и предложение изменить фильтры.
8. Нажмите «Откликнуться» у любой карточки. Адрес должен содержать её ID: `/catalog/{taskId}/respond`.

### Отклик и пустые состояния

1. На странице отклика заполните название команды, идею, план и срок; ссылка на прототип необязательна.
2. После отправки должна появиться ссылка «Проверить статус», а статус нового предложения — «На рассмотрении».
3. Чтобы проверить пустое состояние каталога, в инструментах разработчика браузера на домене приложения задайте `localStorage.setItem("ai-sana:tasks", "[]")` и `localStorage.setItem("ai-sana:demo-seeded", "true")`, затем перезагрузите `/catalog`. Должны появиться «Пока нет опубликованных задач» и кнопка «Создать задачу».
4. Для возврата демонстрационных данных удалите ключ `ai-sana:demo-seeded` и перезагрузите страницу. Инициализатор снова добавит примеры.

### Мобильная ширина

В режиме адаптивного просмотра браузера установите ширину около `375 px`. Каталог должен перейти в одну колонку, фильтры — расположиться по ширине экрана, горизонтальная прокрутка страницы не должна появляться.

## Ограничения

- Задачи, команды и отклики хранятся в `localStorage` и не синхронизируются между разными браузерами или устройствами.
- Каталог получает записи из локального хранилища браузера; это демо-архитектура, не серверный многопользовательский каталог.
- AI-уточнение зависит от серверного OpenAI-ключа и сети; при недоступности API используется демонстрационный fallback.
- В текущей версии нет NVIDIA-интеграции и нет опубликованной ссылки на deployed-версию.
- Текст, предложенный AI, следует проверить и подтвердить перед публикацией.
