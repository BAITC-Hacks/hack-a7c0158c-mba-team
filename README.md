# AI Sana

### От бизнес-проблемы — к понятной задаче и предложению команды

**MVP для HackAlem AI · Команда MBA**

AI Sana помогает бизнесу подготовить практическую задачу, а студенческим командам — найти проект и предложить решение. AI уточняет исходный запрос, рейтинг показывает полноту описания, а решение о публикации и выборе команды остаётся за человеком.

**[Быстрый старт](#быстрый-старт) · [Проверка за 5 минут](#проверка-за-5-минут) · [Как устроен проект](#как-устроен-проект) · [Границы MVP](#границы-mvp)**

> **Для проверяющих:** основной сценарий можно пройти локально без API-ключей. При недоступности AI приложение явно включает демо-режим с тремя фиксированными вопросами. Для проверки обеих ролей используйте один профиль браузера.

---

## Зачем нужен AI Sana

Для совместной работы бизнесу и команде нужно одинаково понимать проблему: кто будет пользоваться решением, какие данные доступны и по каким признакам оценивать результат. Короткого запроса «нужно внедрить AI» для этого недостаточно.

AI Sana проводит бизнес через подготовку карточки, делает пробелы в описании видимыми и собирает предложения команд в одном сценарии.

- **Бизнесу** — уточняющие вопросы, структурированная задача и ручной выбор предложений.
- **Студенческим командам** — каталог задач, понятные критерии готовности и форма отклика с идеей, планом и сроком.
- **Обеим сторонам** — явные ожидания до начала работы и видимый статус решения.

## Что можно сделать в MVP

1. **Описать проблему.** Указать исходную потребность и отрасль.
2. **Уточнить детали.** Получить три вопроса и предложенные поля карточки; проверить и дополнить текст.
3. **Повысить готовность.** Увидеть живой рейтинг, разбивку баллов и подсказки прямо в редакторе.
4. **Опубликовать задачу.** Подтвердить карточку и найти её в каталоге с фильтрами и сортировкой.
5. **Предложить решение.** Отправить от имени команды идею, план, срок и необязательную ссылку на прототип.
6. **Принять решение.** Выбрать или отклонить предложение и увидеть обновлённый статус отклика.

Выбор одной команды не отклоняет остальные автоматически. Задачи с низким рейтингом остаются в каталоге.

## Быстрый старт

**Требования:** Git, Node.js 20.9+ и npm.

```bash
git clone https://github.com/BAITC-Hacks/hack-a7c0158c-mba-team.git
cd hack-a7c0158c-mba-team
npm ci
npm run dev
```

Откройте **http://localhost:3000**. Если порт занят, используйте адрес, который напечатает Next.js в терминале.

Для локального демо файл `.env.local` не обязателен. Чтобы подключить внешние сервисы, создайте его на основе `.env.example`, если такого файла ещё нет, и укажите свои ключи. Не перезаписывайте существующие настройки.

### Первый вход

1. Нажмите **«Войти» → «Регистрация»**.
2. Укажите тестовый e-mail и пароль длиной от 8 символов.
3. Введите шестизначный код, показанный на странице.

В режиме `npm run dev` код отображается в интерфейсе: письма и SMS не отправляются. Учётная запись и сессия сохраняются на сервере.

При первом открытии приложение добавляет **5 синтетических задач, 5 команд и 5 откликов**. Существующие пользовательские данные не затираются.

## Проверка за 5 минут

Пройдите путь **«создание → каталог → отклик → выбор команды»** в одном профиле браузера, на одном адресе и порте.

1. **Создайте задачу.** Например: «Сотрудники магазина вручную распределяют входящие заявки. Нужно ускорить обработку и уменьшить число ошибок».
2. **Ответьте на вопросы и откройте карточку.** Дополните сведения о пользователях, материалах, результате и критериях успеха.
3. **Проверьте живой рейтинг.** Заполните поле «Данные и материалы», затем очистите его: рейтинг изменится на 20 баллов, а подсказка появится снова.
4. **Подтвердите публикацию.** Найдите задачу в каталоге и попробуйте фильтры по теме и готовности.
5. **Отправьте отклик.** Нажмите «Откликнуться», заполните команду, идею, план и срок. Откройте «Проверить статус».
6. **Выберите команду.** Во второй вкладке откройте «Отклики», найдите задачу и примите предложение. Статус в первой вкладке обновится; решение сохранится после перезагрузки.

Подробный сценарий с готовыми примерами: **[сценарий демонстрации](docs/DEMO.md)**.

## AI и контроль человека

Серверный маршрут `POST /api/clarify` получает описание задачи и отрасль. Интеграция использует **OpenAI Responses API**, модель `gpt-4.1-mini` по умолчанию и структурированный ответ по JSON Schema через `text.format`.

Инструкция модели требует опираться на исходный текст, оставлять неподтверждённые поля пустыми и задавать три уточняющих вопроса. Полученный текст остаётся предложением: пользователь редактирует карточку и сам подтверждает публикацию.

- **С API-ключом:** приложение обращается к модели и проверяет формат ответа.
- **Без ключа или при ошибке AI:** возвращает три фиксированных вопроса, сохраняет исходную потребность и явно показывает «Демо-режим».

Таймаут AI-запроса — 20 секунд, максимальный ответ — 1200 токенов. Модель можно изменить через `OPENAI_MODEL`. Реальные вызовы OpenAI и почтового сервиса не входят в автоматические проверки и в текущей подготовке к сдаче не проверялись.

## Прозрачный рейтинг готовности

Рейтинг рассчитывается детерминированно по заполненным полям. Пользователь видит вклад каждого критерия и конкретные шаги для повышения готовности.

- **20 баллов** — контекст и потребность.
- **20 баллов** — данные и материалы.
- **15 баллов** — ожидаемый результат.
- **15 баллов** — критерии успеха.
- **10 баллов** — ограничения.
- **10 баллов** — пользователи.
- **10 баллов** — связь с бизнесом.

В составных критериях баллы делятся поровну между полями.

**0–39 — Черновик · 40–69 — Рабочая · 70–89 — Готовая · 90–100 — Приоритетная**

> Рейтинг измеряет полноту описания, а не достоверность сведений или качество будущего решения. Если данных нет, поле нужно оставить пустым. Низкая готовность не мешает публикации и подаче отклика.

## Как устроен проект

- **Интерфейс:** Next.js App Router, React, TypeScript.
- **Сервер:** Next.js Route Handlers, SQLite через `better-sqlite3`.
- **AI:** OpenAI Responses API со структурированным ответом.
- **Проверки:** TypeScript и браузерные сценарии Playwright.

```text
src/
├── app/
│   ├── api/                   AI-уточнения и авторизация
│   ├── auth/                  Вход и регистрация
│   ├── business/              Создание задач и решения по откликам
│   └── catalog/               Каталог, подача отклика и его статус
├── features/
│   ├── tasks/                 Типы, критерии и расчёт рейтинга
│   ├── proposals/             Формы и управление откликами
│   └── demo/                  Инициализация демонстрационных данных
└── lib/                       SQLite-авторизация и локальное хранилище

tests/                         Сквозные браузерные и API-проверки
docs/DEMO.md                   Сценарий демонстрации
```

Учётные записи, коды, сессии и счётчики лимитов хранятся в **SQLite**. Задачи, команды и отклики — в **`localStorage` браузера**. Изменения доступны во вкладках одного профиля и адреса.

## Проверки качества

При подготовке текущей версии успешно выполнены проверка TypeScript, production-сборка и **2 автоматических сценария**:

- **API:** обязательный вход, валидация, ограничение размера запроса, fallback и лимит частоты, который не обходится сменой IP.
- **Полный пользовательский путь:** регистрация, создание, изменение рейтинга, публикация, отклик, выбор команды, обновление статуса между вкладками и сохранение после перезагрузки. Дополнительно проверяется мобильная ширина.

Для повторного запуска:

```bash
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
```

Тесты запускают отдельный сервер на порте `3107`, используют временную SQLite и пустой API-ключ. Результаты и скриншоты рейтинга сохраняются в `test-results/`.

## Границы MVP

Версия предназначена для демонстрации полного сценария на одном устройстве.

- **Нет общего хранилища между устройствами.** Другой профиль браузера, адрес или порт означает отдельный набор задач и откликов.
- **Нет разграничения владения задачами и ролей.** Авторизация работает на сервере, но смена аккаунта не разделяет локальные данные бизнеса и команды.
- **Нет отдельного редактора после публикации.** Карточку нужно проверить до подтверждения.
- **SMS-подтверждение в production не подключено.** Для регистрации по e-mail нужен настроенный почтовый сервис.

Следующий этап — перенос задач и откликов в общую серверную базу, привязка к владельцам и проверка прав на каждую операцию. Это позволит участникам работать с разных устройств.

## Настройка и развёртывание

<details>
<summary><strong>Переменные окружения</strong></summary>

Используйте `.env.example` как образец для `.env.local`:

- `OPENAI_API_KEY` — серверный ключ OpenAI; без него работает демо-режим.
- `OPENAI_MODEL` — модель AI, по умолчанию `gpt-4.1-mini`.
- `RESEND_API_KEY` — ключ почтового сервиса для production-регистрации.
- `AUTH_EMAIL_FROM` — настроенный адрес отправителя.
- `AI_SANA_DATA_DIR` — каталог постоянного хранения SQLite; по умолчанию `./data`.

`.env.local`, база данных и результаты тестов исключены из Git. Ключи не должны попадать в браузер или иметь префикс `NEXT_PUBLIC_`. Раскрытый ключ необходимо отозвать у провайдера и заменить.

</details>

<details>
<summary><strong>Авторизация и защита AI API</strong></summary>

Пароли хранятся в виде scrypt-хешей. Подтверждение использует одноразовые коды, а серверная сессия — HttpOnly-cookie.

`/api/clarify` требует действующую сессию и ограничивает обращения:

- **5 валидных запросов в минуту на пользователя.** Превышение: `429`, `Retry-After: 60`.
- **100 обращений к OpenAI в час на SQLite-базу**, включая неуспешные. Превышение: `429`, `Retry-After: 3600`.
- **5000 символов описания и 24 000 байт тела запроса.** Неверный ввод: `400`; слишком большое тело: `413`; отсутствие сессии: `401`.

Счётчики обновляются атомарно и сохраняются после перезапуска. Лимит ограничивает число обращений, а не денежные расходы. Для нескольких серверов с отдельными базами потребуется общий лимитер.

</details>

<details>
<summary><strong>Production-запуск</strong></summary>

```bash
npm run build
npm start
```

Нужны Node.js-хостинг, HTTPS и постоянный каталог SQLite с правом записи. Для e-mail-авторизации задайте `RESEND_API_KEY` и `AUTH_EMAIL_FROM`. Текущая production-конфигурация требует этих настроек и для входа подтверждённого пользователя. Коды в production не показываются в браузере.

GitHub Pages не поддерживает серверную часть этой версии: Node.js, SQLite и API требуют соответствующего хостинга. Перед публичной эксплуатацией нужно реализовать общее хранилище и разграничение прав, описанные в разделе «Границы MVP».

</details>
