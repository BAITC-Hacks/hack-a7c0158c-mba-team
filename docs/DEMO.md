# Сценарий защиты AI Sana (4–5 минут)

## Перед выступлением

- Отозвать раскрытый ключ, если он ещё активен. Новый ключ хранить только в `.env.local`.
- Выполнить команды проверки из README. Запустить `npm run dev`, оставить терминал работающим.
- Открыть один браузер на адресе из терминала. Зарегистрироваться по тестовому e-mail, подтвердить показанным локальным кодом, заранее войти.
- Открыть каталог и проверить наличие примеров. Не очищать хранилище используемого профиля: для чистого показа лучше отдельный профиль браузера.
- Выбрать режим показа: настоящий AI с новым ключом и предварительным пробным запросом либо честно обозначенный fallback без ключа. При недоступности AI можно заполнить карточку вручную.

## 1. Проблема и исходное описание (30 секунд)

«Мы помогаем бизнесу превратить размытый запрос в задачу, по которой студенческая команда может предложить решение».

Нажать «Создать задачу», выбрать розничную торговлю и ввести:

> Сотрудники магазина вручную распределяют входящие заявки. Нужно ускорить обработку и уменьшить число ошибок при передаче обращений между операторами.

## 2. Уточнения и рейтинг (90 секунд)

Показать три вопроса. Ответить известными фактами. Для fallback можно использовать:

- Пользователи: операторы поддержки магазина.
- Материалы: обезличенная выгрузка заявок за месяц с категориями.
- Результат: прототип классификации заявок и отчёт о качестве.

Сформировать карточку. Обратить внимание на живой рейтинг. Дополнить:

- Контекст: операторы вручную читают каждую заявку перед назначением отдела.
- Критерии успеха: сравнить точность классификации с текущим способом на отложенных примерах.
- Ограничения: три недели, без персональных данных и доступа к рабочим системам.
- Контакт: руководитель поддержки.
- Взаимодействие: еженедельная встреча и ответы на вопросы в общем чате.

Удалить и вернуть значение поля «Данные и материалы»: показать изменение на 20 баллов и подсказку. Сказать: «Рейтинг измеряет заполненность. Он не проверяет истинность текста; публикацию подтверждает человек». Нажать «Подтвердить и опубликовать».

## 3. Каталог и отклик (60 секунд)

Открыть каталог, найти созданную задачу. Показать фильтр готовности и то, что задачи с низким рейтингом тоже видны. Нажать «Откликнуться»:

- Команда: Data Team.
- Идея: классификатор обращений с ручным подтверждением оператора.
- План: разобрать данные, собрать базовый вариант, оценить ошибки и показать прототип.
- Срок: три недели.

Отправить отклик, открыть его статус. Оставить эту вкладку открытой.

## 4. Решение бизнеса (45 секунд)

В другой вкладке того же профиля открыть «Отклики», найти свою задачу и выбрать команду. Вернуться к статусу команды: он обновляется. Объяснить, что решение принимает человек и остальные команды не отклоняются автоматически.

## 5. Честно обозначить границы (30 секунд)

«Сейчас задачи и отклики живут в браузере, поэтому показываем обе роли на одном устройстве. Авторизация работает через сервер, но владение задачами и роли ещё не разграничены. Следующий шаг — общая база задач и проверка прав, чтобы бизнес и команды могли работать с разных устройств».

Не обещать работающую SMS-проверку, общий каталог между устройствами, AI-ответы без ключа или готовый production-сервис.
